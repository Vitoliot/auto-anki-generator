# Auto Anki Generator

LLM-powered flashcard generation backend in Go with PostgreSQL, Redis Streams, retries, DLQ and crash recovery.

Сервис автоматически формирует карточки интервального повторения на основе учебных материалов. Проект разрабатывается в рамках выпускной квалификационной работы.

## О проекте

Ручное создание качественных карточек занимает много времени. При этом прямое использование LLM не гарантирует стабильный формат, отсутствие повторов и корректную обработку больших материалов.

Auto Anki Generator решает эту задачу с помощью серверного pipeline:

1. принимает учебный материал;
2. сохраняет источник;
3. создает задание на обработку;
4. разбивает материал на части;
5. формирует карточки;
6. проверяет и дедуплицирует результат;
7. сохраняет карточки;
8. предоставляет их через API;
9. экспортирует готовый набор.

## Основные возможности

- управление пользователями;
- загрузка учебных материалов;
- асинхронная обработка заданий;
- разбиение текста на части;
- генерация карточек;
- хранение карточек в PostgreSQL;
- дедупликация результатов;
- отслеживание статуса заданий;
- повторная обработка ошибок;
- dead-letter queue;
- восстановление сообщений после падения worker;
- экспорт карточек.

## Надежная обработка заданий

Для фоновой обработки используются Redis Streams и consumer groups.

Сервис поддерживает:

- повторную обработку сообщений;
- ограничение количества попыток;
- экспоненциальную задержку между попытками;
- перенос необработанных сообщений в DLQ;
- восстановление сообщений из pending entries list;
- работу нескольких экземпляров worker.

При падении worker сообщения возвращаются в обработку через `XAUTOCLAIM`.

## Retry и DLQ

Каждое сообщение содержит номер попытки обработки.

При ошибке:

1. сообщение подтверждается в текущем stream;
2. создается новое сообщение с увеличенным номером попытки;
3. применяется exponential backoff;
4. после исчерпания попыток сообщение переносится в DLQ.

Используемые streams:

```text
parse_jobs
parse_jobs_dlq
gen_jobs
gen_jobs_dlq
```

## LLM-интеграция

Интеграция с моделью изолирована за отдельным интерфейсом, что позволяет подключать различные провайдеры.

```go
type Generator interface {
    GenerateCards(
        ctx context.Context,
        request GenerationRequest,
    ) ([]Card, error)
}
```

В текущей версии используется детерминированная mock-реализация. Она позволяет:

- запускать проект без внешнего API-ключа;
- выполнять воспроизводимые тесты;
- проверять полный processing pipeline;
- разрабатывать инфраструктуру независимо от конкретной модели.

Подключение реального провайдера выполняется через пакет:

```text
internal/infra/llm
```

```bash

cp .env.example .env

```

## Оценка качества генерации

Для оценки качества используются следующие показатели:

- доля ответов, соответствующих ожидаемому формату;
- доля карточек без фактических ошибок;
- количество повторяющихся карточек;
- соответствие карточки исходному материалу;
- доля карточек, не требующих ручного редактирования;
- время обработки материала.

Результаты экспериментов будут размещены в:

```text
docs/evaluation.md
```
